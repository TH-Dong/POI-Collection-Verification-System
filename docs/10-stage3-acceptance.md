# 阶段 3 验收说明

阶段 3 的目标是打通 `采集者提交 POI -> 核验者审核 -> 采集者查看整改意见 -> 整改后重新提交 -> 管理员查看处理进展` 的主业务闭环。

本阶段优先保证：

- 状态流转正确
- 角色职责清晰
- 页面入口明确
- 整改意见可追踪

## 3. 当前支持状态

当前代码已支持以下 POI 状态：

- `DRAFT`
- `SUBMITTED`
- `APPROVED`
- `REJECTED`
- `RESUBMITTED`

对应含义：

- `DRAFT`：草稿，采集者可继续编辑
- `SUBMITTED`：已提交待核验
- `APPROVED`：核验通过
- `REJECTED`：核验不通过待整改
- `RESUBMITTED`：整改后待复核

## 4. 当前主业务链

1. 采集者登录移动端
2. 新建或编辑 POI
3. 提交待核验，状态进入 `SUBMITTED`
4. 核验者在 Web 或移动端进入待核验队列
5. 核验者查看 POI 详情、图片、位置、描述
6. 核验者选择：
   - 通过，状态进入 `APPROVED`
   - 驳回，填写错误标记和整改说明，状态进入 `REJECTED`
7. 采集者在移动端查看整改意见
8. 采集者基于原记录整改并重新提交
9. 状态进入 `RESUBMITTED`
10. 核验者再次复核
11. 管理员在 Web 端查看全链路处理进展

## 5. 当前角色职责

### 5.1 采集者

- 负责创建与提交 POI
- 负责查看整改意见
- 负责修改被驳回记录并重新提交
- 不能修改已通过或正在核验中的记录

### 5.2 核验者

- 只关注待处理队列
- 只处理 `SUBMITTED` 和 `RESUBMITTED`
- 不直接修改采集数据
- 通过“通过 / 驳回整改”给出结论

### 5.3 管理员

- 查看全量处理进展
- 查看不同状态的分布
- 查看最近处理记录和整改轨迹
- 当前阶段不承担具体核验动作
