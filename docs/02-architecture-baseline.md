# 系统架构基线

## 1. 架构目标

本项目采用 `前后端分离 + 模块化单体后端 + 事件驱动消息` 的方案，目标是在保持架构成熟度的同时，将复杂度控制在课程项目可实现范围内。

## 2. 总体架构

```text
React Native Mobile App      React Admin Web
          |                         |
          +----------- HTTP / WebSocket -----------+
                                                    |
                                         Spring Boot Backend
                                                    |
                    +-------------------------------+------------------------------+
                    |               |               |              |               |
                  MySQL           Redis          MinIO         RabbitMQ     External APIs
                                                                        (Map / OCR / WeChat)
```

## 3. 架构风格

- 前端：前后端分离
- 后端：模块化单体
- 通信：REST API + WebSocket + MQ
- 数据：结构化数据 + 非结构化文件分离存储

## 4. 前后端职责划分

### 4.1 移动端

- 采集者、核验者、第三方工作人员共用一个 App
- 根据角色加载对应菜单、页面和权限
- 承载现场拍照、定位、上传、核验、消息沟通等能力

### 4.2 Web 管理端

- 面向系统管理员
- 承载用户管理、规则配置、任务调度、统计分析等能力

### 4.3 后端

- 统一鉴权与权限控制
- 维护业务状态机和流程流转
- 管理 POI、采集、核验、争议、复核、任务、消息等核心模块
- 接入地图、OCR、微信、文件存储等第三方能力

## 5. 模块边界

后端建议划分为以下业务模块：

- `auth`：登录、令牌、用户身份、权限校验
- `user`：用户、角色、组织、数据权限
- `poi`：POI 主对象和基础信息
- `collection`：采集记录、附件、坐标、草稿
- `verification`：核验记录、错误标注、整改要求
- `dispute`：异议、协商、升级、第三方复核
- `task`：采集任务、核验任务、复核任务
- `message`：系统通知、任务消息、私聊、群聊
- `map`：地图筛选、点位查询、导航跳转支撑
- `system`：字典、配置、审计、报表

## 6. 分层设计

### 6.1 接口层

- App API
- Admin API
- WebSocket 接口

职责：

- 参数校验
- 返回统一响应
- 不承载核心业务规则

### 6.2 应用层

- 编排业务流程
- 控制事务边界
- 触发领域服务与消息事件

### 6.3 领域层

- 维护业务规则
- 维护状态机
- 维护角色行为约束

### 6.4 基础设施层

- 数据库访问
- Redis 缓存
- 对象存储
- MQ 消息
- 第三方接口适配

## 7. 技术基线建议

- 移动端：`React Native + TypeScript`
- 管理端：`React + TypeScript + Ant Design`
- 后端：`Spring Boot 3 + Java 17`
- 数据库：`MySQL 8`
- 缓存：`Redis`
- 文件存储：`MinIO`
- 消息中间件：`RabbitMQ`
- 实时通信：`WebSocket`
- 地图：`高德地图`
- OCR：`百度 OCR` 或 `腾讯 OCR`

## 8. 为什么不直接采用微服务

- 当前业务复杂度主要来自流程协作，而非高并发或多团队并行开发
- 微服务会显著增加部署、注册、调用链、分布式事务和调试成本
- 模块化单体已经足以体现清晰边界和真实工程实践
- 未来若需要，可将消息、聊天、搜索等模块独立拆出
