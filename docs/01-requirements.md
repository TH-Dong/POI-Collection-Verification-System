# 需求说明

## 1. 项目目标

本项目面向 `POI 数据采集、核验、争议处理、最终确认` 的完整业务链，建设一套同时支持移动端和 Web 管理端的协同系统。

业务目标如下：

- 建立 POI 数据从现场采集到结果确认的闭环处理机制
- 保证 POI 数据具备图片、坐标、分类、描述、处理过程等核验依据
- 支持采集者、核验者、第三方工作人员围绕同一条 POI 协作
- 支持系统管理员对用户、任务、规则、消息和统计进行统一管理
- 支持地图、OCR、微信、消息中间件等外部能力接入

## 2. 系统范围

### 2.1 纳入本项目的范围

- POI 采集与提交
- POI 核验与标错
- 整改回传与重新提交
- 异议处理与第三方复核
- 任务通知、私聊、群聊
- 地图查询与导航跳转
- 管理后台配置和统计

### 2.2 不纳入第一阶段的范围

- 智能自动判错
- 多租户 SaaS 化
- 大规模离线地图自研
- 复杂工作流引擎

## 3. 角色与职责

| 角色 | 核心职责 | 主要目标 |
|---|---|---|
| 采集者 | 现场采集 POI 信息并响应返工 | 快速、准确、完整地提交 POI |
| 核验者 | 审核 POI 数据并提出问题 | 发现错误、推动问题闭环 |
| 第三方工作人员 | 对争议 POI 进行独立复核 | 给出最终裁定结论 |
| 系统管理员 | 管理账号、任务、规则、统计和审计 | 保证系统稳定和业务有序流转 |

## 4. 核心业务对象

- `POI`：系统管理的地点主对象
- `采集记录`：一次采集提交产生的结构化记录
- `核验记录`：核验者对某次采集结果的审核记录
- `整改单`：核验不通过后生成的整改要求
- `争议单`：双方无法达成一致时的协商与升级载体
- `复核记录`：第三方现场复核后的最终结论
- `任务`：采集任务、核验任务、复核任务
- `通知/消息`：系统通知、任务通知、私聊消息、群聊消息
- `附件`：图片、补充证明材料

## 5. 角色用例

### 5.1 采集者

- 登录系统并维护个人信息
- 拍照上传 POI 图片
- 自动获取位置并随图片上传
- 填写 POI 分类、名称、描述
- 查看自己提交的 POI 与处理状态
- 接收重新采集或整改要求
- 对异议进行补充、更新、重新采集或驳回
- 与核验者私聊讨论错误详情

### 5.2 核验者

- 接收并处理核验任务
- 查看 POI 图片、位置、描述和历史记录
- 提交核验结论
- 标记错误、填写错误说明
- 在地图上筛选 POI 并查看分布
- 使用导航前往指定 POI
- 跟踪整改状态并再次核验
- 发起争议升级

### 5.3 第三方工作人员

- 接收争议升级任务
- 查看争议背景与历史处理记录
- 到现场重新采集/复核
- 提交最终结果和证据

### 5.4 系统管理员

- 管理用户、角色、权限、组织
- 管理 POI 分类、错误类型、流程规则
- 分配和监控采集/核验/复核任务
- 群发通知
- 查看统计分析和审计日志

## 6. 功能模块清单

- 用户与权限模块
- POI 采集模块
- POI 核验模块
- 异议与复核模块
- 地图查询模块
- 消息与协作模块
- 任务管理模块
- 管理后台模块
- 外部集成模块

## 7. 非功能需求

### 7.1 性能

- 地图筛选和 POI 列表响应可接受
- 图片上传支持失败重试
- 消息通知具备较好的及时性

### 7.2 可靠性

- 图片、位置、核验记录、争议记录不可丢失
- 状态流转需有留痕
- 通知失败需支持补偿或重试

### 7.3 安全性

- 登录鉴权安全
- 角色权限隔离
- 关键操作审计留痕
- 敏感配置信息安全存储

### 7.4 可扩展性

- 地图服务可替换
- OCR 服务可替换
- 消息中间件可替换
- 后续角色和流程层级可扩展
