# 阶段 7 验收说明：私聊、群聊与协作增强

## 1. 阶段目标

阶段 7 的目标是补齐角色之间的实时协作能力，让采集者、核验者和管理端可以围绕 POI 直接沟通，并保留完整留痕。

## 2. 本阶段实际完成内容

### 2.1 后端

已完成：

- 新增 `im_conversation`、`im_conversation_member`、`im_message`
- 新增 WebSocket 入口：`/ws/chat`
- 支持 `采集者协作群`、`核验者协作群`
- 支持围绕 `POI` 自动创建核验者与采集者私聊
- 支持聊天消息持久化、未读计数、已读回写
- 支持用户在线状态感知
- 支持在 `POI` 详情页查询关联沟通记录
- 新消息自动复用阶段 6 的通知模型，生成 `CHAT` 类型提醒

### 2.2 管理端

已完成：

- 新增“协作会话”页
- 支持会话列表、消息流、发送消息
- 支持 WebSocket 实时刷新会话和消息
- 支持从 `POI 详情` 直接打开关联私聊
- 支持在 `POI 详情` 查看历史沟通留痕

### 2.3 移动端

已完成：

- 首页增加“协作会话”入口和未读会话统计
- 新增会话列表页
- 新增聊天详情页
- 采集者 `PoiDetailScreen` 可直接联系核验者
- 核验者 `VerifierPoiDetailScreen` 可直接联系采集者
- `POI` 详情页支持查看当前点位沟通记录

## 3. 当前能力边界

当前阶段 7 重点覆盖：

- `POI` 关联私聊
- 采集者群聊
- 核验者群聊
- WebSocket 实时接收消息
- 会话未读数
- 站内聊天提醒
- 沟通历史留痕

当前未扩展：

- 自定义群组创建
- 文件消息 / 图片消息
- 撤回、删除、转发
- 跨组织复杂在线状态统计

## 4. 验收路径

### 4.1 移动端私聊

1. 使用 `collector / 123456` 登录移动端
2. 打开任意一条 `SUBMITTED`、`REJECTED` 或 `RESUBMITTED` 的 POI 详情
3. 点击“联系核验者”
4. 应跳转到聊天详情页
5. 发送消息后，消息应保存在会话中

### 4.2 核验者移动端回复

1. 使用 `verifier / 123456` 登录移动端
2. 进入“协作会话”
3. 打开与采集者的 POI 私聊
4. 应能看到采集者刚发送的消息
5. 回复后，采集者重新进入会话应能看到实时或刷新后的新消息

### 4.3 管理端会话中心

1. 使用 `verifier / 123456` 或 `admin / 123456` 登录管理端
2. 进入左侧“协作会话”
3. 应能看到角色群聊和 POI 私聊
4. 选择任意会话后，应看到消息记录
5. 发送消息后，会话列表和详情应实时刷新

### 4.4 POI 留痕

1. 在移动端或管理端对某个 POI 发送几条协作消息
2. 返回该 `POI` 详情页
3. “沟通记录 / 沟通留痕”区域应展示这些消息
4. 发送人和时间应可见

### 4.5 未读消息

1. 让一方在会话中发送消息
2. 另一方不要立即进入该会话
3. 会话列表应显示未读数
4. 移动端首页应显示未读会话数
5. 打开会话后，未读数应清零
